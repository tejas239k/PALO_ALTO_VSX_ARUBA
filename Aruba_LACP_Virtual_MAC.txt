Here is why your logic about LACP and virtual MACs works differently in the backend, and where that configuration actually lives:


1. Why LACP Doesn't Need a "Virtual Switch MAC"
LACP (Link Aggregation Control Protocol) operates at the physical/data-link layer (IEEE 802.3ad).
When PaloAlto1 forms an LACP bundle (ae1) with your Aruba core switches, LACP doesn't look at "switch IP gateways" or virtual router MAC addresses to decide how to bundle cables.
Instead, LACP uses system MAC addresses and system priorities. Each physical switch (ArubaCX3 and ArubaCX7) has its own unique hardware base MAC address, but when they form an MC-LAG, the VSX protocol coordinates them behind the scenes so they present a shared, unified system MAC and system ID to the firewall.
To the Palo Alto firewall, the LACP negotiation packets coming from both switches appear as if they are originating from a single logical partner. You don't need to manually configure a virtual MAC for LACP because VSX handles that identity synchronization automatically in the background.



2. Where Do We Use a Virtual MAC in Your Aruba Setup?
We did talk about a virtual MAC earlier, but it belongs to the Active Gateway feature for client routing, not LACP.
When your switches act as Layer 3 gateways for clients, both switches need to share the exact same gateway IP and MAC address so that client PCs can send packets to either switch seamlessly without ARP confusion.
That configuration looks like this on the SVI interface:

interface vlan 10
    no shutdown
    ip address 10.10.10.2/24              ! Unique IP for Primary switch
    active-gateway ip 10.10.10.1 mac 00:00:00:00:01:01   ! The Virtual Gateway MAC
exit


(Note: In your current updated topology, since we moved the SVI gateways up to the Palo Alto firewall subinterfaces ae1.10 and ae1.20 for security inspection, the Active Gateway configuration isn't even needed on the Aruba switches anymore the Palo Alto handles that routing role directly!)
Summary
For LACP (ae1 bundling): VSX automatically synchronizes the system identity behind the scenes so the firewall sees a single logical partner. No manual virtual MAC command is required for the port-channel itself.
For Layer 3 Gateways: If your switches ever hold the gateway IPs for end-users, the virtual MAC is defined using the active-gateway ip [IP] mac [MAC] command under the VLAN interface.
